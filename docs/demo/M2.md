# M2a demo — Menu (API, domain, CSV import)

```bash
pnpm db:reset      # migrations 0001–0003, demo branch (stations, price lists), dev users
pnpm dev           # api on http://localhost:18080
```

## Import the sample desi menu

[docs/samples/desi-menu.csv](../samples/desi-menu.csv) — 30 items / 37 variants / 8 categories, Urdu + English, three price lists (prices are illustrative placeholders). One row = one variant; rows without a category belong to the previous item or category as written in the file.

```powershell
$base = 'http://localhost:18080/api/v1'
$t = Invoke-RestMethod -Method Post "$base/auth/login" -ContentType application/json -Body '{"username":"manager","password":"Dev#Passw0rd"}'
$h = @{ Authorization = "Bearer $($t.accessToken)" }
$csv = [IO.File]::ReadAllBytes("docs/samples/desi-menu.csv")

# 1. dry run (the default): validates everything, changes nothing
Invoke-RestMethod -Method Post "$base/menu/import" -Headers $h -ContentType 'text/csv; charset=utf-8' -Body $csv
# 2. apply (all-or-nothing, audited)
Invoke-RestMethod -Method Post "$base/menu/import?dryRun=false" -Headers $h -ContentType 'text/csv; charset=utf-8' -Body $csv
# 3. what the POS loads (one payload, ETag + 304)
Invoke-RestMethod "$base/menu?priceList=DINE_IN" -Headers $h
Invoke-RestMethod "$base/menu/warnings" -Headers $h               # items hidden on a channel (no price)
# 4. export (UTF-8 with BOM, opens in Excel with Urdu intact); re-importing it changes nothing
Invoke-RestMethod "$base/menu/export.csv" -Headers $h -OutFile menu-export.csv
```

## CSV format

| Column | Meaning |
| --- | --- |
| `item_code` (required) | stable key; rows with the same code are one item |
| `item_name` (required) | English name; `item_name_ur`, `category`, `category_ur` optional |
| `kind` | `STANDARD` (default) or `WEIGHT` (price is per kg; variant "Per kg"). Deals are created in the app |
| `station` | KOT station code (BBQ, TANDOOR, …) — must exist |
| `variant`, `variant_ur` | Half / Full / Piece … ; omit for single-variant items (named "Regular") |
| `price_<list>` | one column per price list, rupees (`1250`, `1,250.50`); **blank = not sold on that channel** |
| `search_terms` | Roman-Urdu / alias words for POS search |
| `available` | `yes` / `no` (the 86 toggle) |

Blank optional cells leave existing values unchanged. Imports never delete anything.

## Main endpoints (all under `/api/v1`)

| Area | Endpoints | Needs |
| --- | --- | --- |
| Categories | `GET/POST /categories`, `PATCH /categories/:id` | read: any · write: `menu.manage` |
| Items | `GET /items`, `GET /items/:id`, `POST /items`, `PATCH /items/:id` | read: any · write: `menu.manage` |
| 86 toggle | `PATCH /items/:id/availability` | `menu.availability` (cashier, kitchen, manager, owner) |
| Variants / prices | `POST /items/:id/variants`, `PATCH /variants/:id`, `PUT /variants/:id/prices/:priceListId` `{pricePaisa, effectiveFrom?}` | `menu.manage` |
| Modifiers | `GET/POST /modifier-groups`, `PATCH /modifier-groups/:id`, `POST /modifier-groups/:id/modifiers`, `PATCH /modifiers/:id`, `PUT /items/:id/modifier-groups` | `menu.manage` |
| Deals | `PUT /items/:id/deal` `{slots:[{name, qty, options:[{variantId, priceDeltaPaisa?, isDefault?}]}]}` | `menu.manage` |
| POS payload | `GET /menu?priceList=DINE_IN&date=YYYY-MM-DD` (ETag / 304) | any user |
| Admin | `GET /menu/warnings`, `GET /menu/export.csv`, `POST /menu/import` | `menu.manage` |

Design: [ADR 0003](../adr/0003-menu-model.md). Error codes: [ERROR-CODES.md](../ERROR-CODES.md) (domain rule violations return `VALIDATION_FAILED` with a `reason` such as `DEAL_SLOT_COUNT`).

## What the tests prove

- **Domain (97 tests, 100 % branch coverage on money/price/modifiers/deals/categories, 98 % on the import planner):** rupee parsing (table + property tests), price lookup by list and business date (inclusive boundaries, gaps, overlaps), modifier min/max rules, deal selection rules (+ property test: any split of a slot sums to its qty), category cycles, CSV validation + diff planning (idempotent).
- **Database:** price periods cannot overlap; deal slots only on DEAL items; no nested deals; item kind frozen once it has orders; one default variant; case-insensitive uniqueness; `0003` upgrades a populated database.
- **API:** permission matrix extended with 16 menu endpoints × 7 roles; item/variant/price/modifier/deal rules; price history; POS payload per channel and date; ETag/304 and cache invalidation on every kind of write; branch isolation; 86 toggle by role; 300-item payload speed.
- **CSV:** dry run vs apply, atomic rejection with line numbers, idempotent re-import, export → import round trip, Urdu + quoted commas, price history on change, future-dated block, kind/deal protection, 1 500 rows in one transaction.
