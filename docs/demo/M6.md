# Demo — M6a: billing and payments (tax-free)

Start the stack (`pnpm dev`), sign in as `cashier` / PIN `1234` (dev seed; see M1.md).

## In the browser

1. **Open the day and a shift** (top bar), tap a free table, add *Chicken Tikka* and tap **Send to kitchen**.
   The **Bill** button stays disabled while any line is unsent.
2. Tap **Bill** → the payment screen shows the server-priced bill (subtotal, service charge and round-off if configured, total).
3. **Discount:** pick 10 %, type a reason, **Apply** (within the cashier's 10 % limit). Pick 20 % → a *Manager approval needed* box asks for `manager` + PIN `1234`; a wrong PIN is refused (and counts towards lockout).
4. **Pay:** tap **+ Cash**, type the cash received or a quick amount (500 / 1000 / 5000) → **Settle bill** → big **change to return**. Or split: set cash to a part, tap **+ Debit/Credit Card** for the rest (card needs a reference). The button stays disabled until the amounts add up exactly.
5. The receipt prints on the RECEIPT printer (cash opens the drawer). **Reprint receipt** prints a copy marked `DUPLICATE #1` (reason recorded in the audit log).
6. Managers can **Cancel bill** (reason required) on an unpaid bill; the order reopens for changes.

## With curl

```bash
# pre-bill, then pay Rs 1,000 cash for a Rs 650 bill (change Rs 350)
curl -X POST $API/orders/$ORDER/bill -H "Authorization: Bearer $T" -H 'If-Match: 5'
curl -X POST $API/bills/$BILL/settle -H "Authorization: Bearer $T" \
  -H 'Idempotency-Key: pay-2026-11-10-0001' -H 'content-type: application/json' \
  -d '{"tenders":[{"methodId":"<cash id>","amountPaisa":65000,"tenderedPaisa":100000}]}'
# the same key again → 200, "replayed": true, nothing is charged twice
```

## What the tests prove

- `bills.test.ts` (22): totals with/without service charge and round-off, unsent items, order frozen, discount limit + approval + wrong PIN + audit, cash/change, split, card reference, under/over-payment, khata refused, idempotent replay, 4 parallel settles → 1 payment, shift required, settled bills immutable, DB guards, void, reprint, branch scoping.
- Playwright `04-billing.spec.ts`: the three flows above against a fake receipt printer (drawer-kick bytes, DUPLICATE copy).
- Permission matrix probes for all five billing endpoints × 7 roles.
