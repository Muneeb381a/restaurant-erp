# M1 demo — Auth, RBAC, setup

```bash
pnpm db:reset     # migrates (0001 + 0002) and seeds the demo branch + one dev user per role
pnpm dev          # api on http://localhost:18080
```

Dev logins (public, dev only): password `Dev#Passw0rd`, PIN `1234`, usernames `owner manager cashier captain kitchen store accountant`.

## Try it (PowerShell)

```powershell
$base = 'http://localhost:18080/api/v1'
$t = Invoke-RestMethod -Method Post "$base/auth/login" -ContentType application/json -Body '{"username":"owner","password":"Dev#Passw0rd"}'
$h = @{ Authorization = "Bearer $($t.accessToken)" }
Invoke-RestMethod "$base/auth/me" -Headers $h                       # role + 29 permissions
Invoke-RestMethod -Method Post "$base/areas" -Headers $h -ContentType application/json -Body '{"name":"Main Hall"}'
Invoke-RestMethod "$base/audit-log?limit=5" -Headers $h              # LOGIN, AREA_CREATE, ...

$c = Invoke-RestMethod -Method Post "$base/auth/login-pin" -ContentType application/json -Body '{"username":"cashier","pin":"1234"}'
# the cashier is refused (403 PERMISSION_DENIED) when creating an area:
Invoke-RestMethod -Method Post "$base/areas" -Headers @{Authorization="Bearer $($c.accessToken)"} -ContentType application/json -Body '{"name":"x"}'
```

Owner-level users (`owner`) are not tied to a branch: with several branches send `x-branch-id`.

## Endpoints (all under `/api/v1`)

| Area         | Endpoints                                                                                                      | Needs                                  |
| ------------ | -------------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| Auth         | `POST /auth/login`, `/auth/login-pin`, `/auth/refresh`, `/auth/logout`; `GET /auth/me`                         | public / bearer                        |
| Users        | `GET/POST /users`, `PATCH /users/:id`, `POST /users/:id/credentials`, `POST /users/:id/unlock`                 | `user.manage`                          |
| Roles        | `GET /roles`, `GET /permissions`, `POST /roles`, `PUT /roles/:id/permissions`                                  | `user.manage`                          |
| Branch       | `GET/PATCH /branch`, `GET /settings`, `PUT /settings/:key`                                                      | `settings.manage` (`tax.manage` for tax fields/keys) |
| Floor/config | `/areas`, `/tables`, `/stations` (+ `PUT /stations/:id/printers`), `/printers`, `/payment-methods`, `/price-lists` | read: any user · write: `settings.manage` |
| Devices      | `GET/POST /devices`, `PATCH /devices/:id` (revoke)                                                             | `device.manage`                        |
| Audit        | `GET /audit-log?limit&before&entity&entityId&action&userId` (keyset, newest first, read-only)                  | `audit.view`                           |

Error codes: [docs/ERROR-CODES.md](../ERROR-CODES.md). Design decisions: [ADR 0002](../adr/0002-auth-and-rbac.md).

## What the tests prove (`pnpm test`)

- **Permission matrix:** 7 seeded roles × every sensitive endpoint (23 in M1, 39 since M2) (allowed vs `403 PERMISSION_DENIED`), plus 401 without a token, plus the exact permission set of every role.
- **Login:** PIN/password, case-insensitive username, uniform error for unknown/inactive/wrong, lockout after 5 failures (window, expiry, shared counter, concurrent guessing), reset on success.
- **Sessions:** refresh rotation + reuse detection, logout, access/refresh expiry, deactivation/role change cut sessions immediately, device binding and revocation.
- **Audit:** rows for login/logout/failures and every user/role/config change (with before/after), no credentials in them, keyset pagination, branch scoping, append-only at DB level.
- **Safety rules:** no privilege escalation, OWNER role protected, last owner protected, branch isolation (404), `branch_id` never client-supplied.
- **Migration:** `0002` upgrades a populated `0001` database without touching data.
