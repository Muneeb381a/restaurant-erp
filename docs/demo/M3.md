# M3a demo — Floor & orders (API + domain)

```bash
pnpm db:reset      # migrations 0001–0004 + demo branch + dev users
pnpm dev           # api on http://localhost:18080
```

Import the sample menu first ([M2 demo](M2.md)), create a few tables (`POST /tables {"code":"T1","seats":4}`), then:

```powershell
$base = 'http://localhost:18080/api/v1'
function Login($u, $p) { $t = Invoke-RestMethod -Method Post "$base/auth/login" -ContentType application/json -Body (@{username=$u;password=$p}|ConvertTo-Json); @{ Authorization = "Bearer $($t.accessToken)" } }
$cashier = Login 'cashier' 'Dev#Passw0rd'; $captain = Login 'captain' 'Dev#Passw0rd'; $manager = Login 'manager' 'Dev#Passw0rd'

Invoke-RestMethod -Method Post "$base/business-days/open" -Headers $cashier -ContentType application/json -Body '{}'
Invoke-RestMethod -Method Post "$base/shifts/open" -Headers $cashier -ContentType application/json -Body '{"openingFloatPaisa":500000}'

$tables = (Invoke-RestMethod "$base/tables" -Headers $captain).items
$order  = Invoke-RestMethod -Method Post "$base/orders" -Headers $captain -ContentType application/json -Body (@{type='DINE_IN';tableId=$tables[0].id;guests=4}|ConvertTo-Json)

$menu = Invoke-RestMethod "$base/menu?priceList=DINE_IN" -Headers $captain
$tikka = $menu.items | Where-Object code -eq 'TIKKA-LEG'
Invoke-RestMethod -Method Post "$base/orders/$($order.id)/items" -Headers $captain -ContentType application/json `
  -Body (@{itemId=$tikka.id;variantId=$tikka.variants[0].id;qty=3}|ConvertTo-Json)   # server prices it: Rs 1,080
Invoke-RestMethod "$base/floor" -Headers $captain                                    # T1 = OCCUPIED, 1 item, Rs 1,080
```

## Endpoints (all under `/api/v1`)

| Area | Endpoints | Needs |
| --- | --- | --- |
| Day / shift | `GET /business-days/current`, `POST /business-days/open`, `GET /shifts/current`, `POST /shifts/open {openingFloatPaisa, deviceId?}` | `day.open` · `shift.open` |
| Floor | `GET /floor` (tables + live status + order summary), `GET /orders?status&type&held&limit`, `GET /orders/:id` | any user |
| Orders | `POST /orders {type, tableId?, guests?, customerId?, notes?, channel?, priceList?}`, `PATCH /orders/:id`, `POST /orders/:id/hold`, `…/resume` | `order.create` |
| Lines | `POST /orders/:id/items {itemId, variantId, qty?, weightG?, modifierIds?, dealPicks?, note?, course?}`, `PATCH /orders/:id/items/:lineId`, `POST /orders/:id/items/:lineId/void {reason}` | `order.create` (+ `kot.void` once sent) |
| Table moves | `POST /orders/:id/transfer {tableId}`, `POST /orders/:id/merge {sourceOrderId}` | `order.transfer` |
| Cancel | `POST /orders/:id/cancel {reason}` | `order.cancel` |

Every order response carries `version` and an `ETag`. Send it back as `If-Match` — **required** for `PATCH /orders/:id`, transfer, merge and cancel; optional (but checked) for line commands. Errors: [ERROR-CODES.md](../ERROR-CODES.md). Design: [ADR 0004](../adr/0004-orders-and-concurrency.md).

## What the tests prove

- **Domain (137 tests, 100 % branch coverage on money, allocation, line pricing, order/item state):** `mulDivHalfUp` (half-up rounding, property test vs exact quotient), `allocateProRata` (Σ parts = whole — property tests), `priceLine` for STANDARD / WEIGHT / DEAL with modifiers (property: weighed price within ½ paisa of exact; two half-kilos differ from a kilo by ≤ 1 paisa), deal allocation, void/edit rules, order state machine.
- **Database:** order lines and their modifiers are frozen once the order is SETTLED/CANCELLED (kitchen status progression still allowed); one open shift per cashier and per till.
- **API (orders.test.ts):** day/shift rules; order numbering; table occupancy incl. **6 captains racing for one table → exactly one wins**; server-side pricing of standard/half-full/weighed/modifier/deal lines; 86, not-on-channel, inactive and foreign items refused; price snapshot stability; **10 parallel adds → no lost update, version +10**; `If-Match` rules (428/409 with `currentVersion`); edit/void rules incl. permission + reason + audit + wastage; hold/resume; transfer (incl. two orders racing for one free table); merge (lines **and KOTs** move, source cancelled, table freed, opposite merges cannot deadlock); cancel rules; branch isolation; permission matrix extended with 12 order endpoints.
