# API error codes

Errors are RFC 7807 `application/problem+json` with a stable `code`. Codes are never renamed or reused; new ones are only added. Every response carries `requestId` (also the `x-request-id` header).

| Code                         | HTTP    | Meaning                                                                                                                                                                                           |
| ---------------------------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `VALIDATION_FAILED`          | 400     | Request body/query/params invalid (Zod `issues` included), unknown setting key, malformed JSON                                                                                                    |
| `BRANCH_REQUIRED`            | 400     | Owner-level user did not send a valid `x-branch-id` and there is not exactly one active branch                                                                                                    |
| `MENU_NOT_PUBLIC`            | 404     | The QR/customer menu is switched off (Admin → QR menu); only the public menu endpoint returns this                                                                                                |
| `RATE_LIMITED`               | 429     | Too many requests from one address to the public menu in a minute                                                                                                                                 |
| `UNAUTHENTICATED`            | 401     | Missing/invalid/expired access token, revoked or expired session, invalid refresh token                                                                                                           |
| `INVALID_CREDENTIALS`        | 401     | Wrong username / password / PIN (deliberately identical for unknown users, inactive users and a device of another branch)                                                                         |
| `REFRESH_REUSED`             | 401     | A superseded refresh token was replayed; the session has been revoked                                                                                                                             |
| `DEVICE_INVALID`             | 401     | `x-device-token` unknown or revoked                                                                                                                                                               |
| `PERMISSION_DENIED`          | 403     | Authenticated but lacking the permission (`permission` field names it) or attempting privilege escalation (`missing` lists the permissions)                                                       |
| `NOT_FOUND`                  | 404     | No such route, or the resource does not exist **in your branch**                                                                                                                                  |
| `CONFLICT`                   | 409     | Unique value already exists, or an action on yourself that is not allowed (e.g. deactivating your own account)                                                                                    |
| `REFERENCE_VIOLATION`        | 409     | Foreign-key conflict (referenced row missing, or still in use)                                                                                                                                    |
| `IDEMPOTENCY_KEY_REUSED`     | 409     | The `Idempotency-Key` sent when adding a dish was already used on a different order. A repeat of the same command on the same order is not an error: it returns the first answer and adds nothing |
| `IN_USE` | 409 | The thing is in use right now (a dish or size on an open order, a table with an open order, a dish inside a deal) or, for a station, area or printer, earlier records point at it. A dish, size or table that only has history is archived instead of refused (ADR 0028) |
| `CONSTRAINT_VIOLATION`       | 400/409 | A database CHECK failed (400) or an immutability/append-only guard blocked the operation (409)                                                                                                    |
| `ROLE_PROTECTED`             | 409     | The OWNER role's permissions cannot be edited                                                                                                                                                     |
| `LAST_OWNER`                 | 409     | The last active owner cannot be deactivated or demoted                                                                                                                                            |
| `ACCOUNT_LOCKED`             | 423     | 5 failed logins within 10 minutes; `retryAfterSeconds` says when to retry. An admin can `POST /users/:id/unlock`                                                                                  |
| `DAY_NOT_OPEN`               | 409     | No business day is open (open it before taking orders or opening a shift)                                                                                                                         |
| `DAY_ALREADY_OPEN`           | 409     | A business day is already open for the branch                                                                                                                                                     |
| `SHIFT_ALREADY_OPEN`         | 409     | The cashier (or the till/device) already has an open shift                                                                                                                                        |
| `TABLE_OCCUPIED`             | 409     | The table already has an open order (`orderId` / `orderNo` in the body)                                                                                                                           |
| `ORDER_NOT_EDITABLE`         | 409     | The order is BILLED / SETTLED / CANCELLED and can no longer be changed                                                                                                                            |
| `ORDER_HELD`                 | 409     | The order is parked; resume it first                                                                                                                                                              |
| `ORDER_HAS_SENT_ITEMS`       | 409     | Cancel refused: void the items already sent to the kitchen first                                                                                                                                  |
| `ITEM_NOT_EDITABLE`          | 409     | The line was already sent (edit = void + re-add) or is already void                                                                                                                               |
| `ITEM_UNAVAILABLE`           | 409     | The item (or a deal component) is sold out (86) or no longer offered                                                                                                                              |
| `ITEM_NOT_ON_MENU`           | 409     | The item has no price in this order's price list for the business date                                                                                                                            |
| `EMPTY_ORDER`                | 409     | Pre-bill refused: the order has no live lines                                                                                                                                                     |
| `UNSENT_ITEMS`               | 409     | Pre-bill refused: some lines were never sent to the kitchen (`items` lists them)                                                                                                                  |
| `BILL_NOT_PAYABLE`           | 409     | The bill is not PRE_BILLED (already settled/void), so it cannot be discounted, paid, voided; reprint needs a settled bill                                                                         |
| `BILL_ALREADY_SETTLED`       | 409     | Settle with a _different_ `Idempotency-Key` on a paid bill (the same key replays the original result with 200)                                                                                    |
| `DISCOUNT_APPROVAL_REQUIRED` | 403     | Discount above the user's `discount_limit_bps`; send `approver: {username, pin}` of a user with `bill.discount.unlimited`                                                                         |
| `APPROVER_INVALID`           | 403     | Approver username/PIN wrong, or that user cannot approve discounts (failed PINs count towards the lockout)                                                                                        |
| `SHIFT_NOT_OPEN`             | 409     | The cashier has no open shift in the bill's business day                                                                                                                                          |
| `VARIANCE_NOTE_REQUIRED`     | 400     | Shift close: counted cash differs from expected; send `notes` (the body has `variancePaisa`)                                                                                                      |
| `TAX_RULE_MISSING`           | 409     | Tax is on but no rule covers a line's category / payment class / date: the bill is NOT priced with a guess (`categoryId`, `paymentClass`, `date`)                                                 |
| `TAX_RULE_AMBIGUOUS`         | 409     | Two rules apply to the same line (`ruleIds`); fix the rules                                                                                                                                       |
| `TAX_NOT_READY`              | 409     | Switching tax on refused; `problems` lists what is missing (authority, rule, unverified rule)                                                                                                     |
| `NOTHING_TO_REFUND`          | 409     | Credit note refused: every line of the bill was already returned                                                                                                                                  |
| `KHATA_NOT_ON_BILL`          | 409     | Refund to khata on a bill that was not put on khata                                                                                                                                               |
| `KHATA_REFUND_EXCEEDS`       | 409     | Refund to khata is more than the bill charged to khata (`maxPaisa` says what is left)                                                                                                             |
| `KHATA_LIMIT_EXCEEDED`       | 409     | Credit sale would pass the customer's limit; body has `balancePaisa`, `limitPaisa`, `availablePaisa`                                                                                              |
| `KHATA_OVERPAYMENT`          | 409     | A khata payment is larger than the balance (advance deposits are not supported); body has `balancePaisa`                                                                                          |
| `KHATA_PHONE_EXISTS`         | 409     | The phone number already belongs to another customer (compared by its last ten digits, so formatting does not matter); the message names them                                                     |
| `KHATA_ACCOUNT_INACTIVE`     | 409     | The khata account is switched off and takes no new credit sales                                                                                                                                   |
| `SHIFTS_STILL_OPEN`          | 409     | Day close refused: some shifts are open (`cashiers` lists them)                                                                                                                                   |
| `ORDERS_STILL_OPEN`          | 409     | Day close refused: orders still OPEN or BILLED (`orders` lists number and status)                                                                                                                 |
| `NOTHING_TO_SEND`            | 409     | Send/reprint found nothing to print (no NEW lines, or every line of the KOT was voided)                                                                                                           |
| `STATION_MISSING`            | 409     | Some items have no kitchen station, so nothing was sent (`items` lists them)                                                                                                                      |
| `NO_PRINTER`                 | 409     | The station of this KOT has no active printer                                                                                                                                                     |
| `KOT_CANCELLED`              | 409     | The kitchen ticket was cancelled and cannot move                                                                                                                                                  |
| `KOT_BAD_MOVE`               | 409     | Ticket moves are NEW → PREPARING → READY → DONE (one step back allowed)                                                                                                                           |
| `VERSION_CONFLICT`           | 409     | `If-Match` does not match; `currentVersion` says what the order is now                                                                                                                            |
| `PRECONDITION_REQUIRED`      | 428     | A structural change needs the order version in `If-Match`                                                                                                                                         |
| `PASSWORD_CHANGE_REQUIRED`   | 403     | A temporary password is still in use: only `/auth/me`, `/auth/change-password` and `/auth/logout` are served until it is changed                                                                  |
| `TENANT_NOT_FOUND`           | 404     | (cloud) no restaurant has that code, or it is archived                                                                                                                                            |
| `TENANT_SUSPENDED`           | 403     | (cloud) the restaurant is switched off; the body has `name` and, when given, `reason`                                                                                                             |
| `TENANT_UNAVAILABLE`         | 503     | (cloud) the restaurant is still being set up, or its setup failed                                                                                                                                 |
| `TENANT_SLUG_INVALID`        | 400     | (cloud) the restaurant code is badly shaped or reserved                                                                                                                                           |
| `TENANT_SLUG_TAKEN`          | 409     | (cloud) another restaurant already has that code                                                                                                                                                  |
| `TENANT_BAD_STATE`           | 409     | (cloud) the action does not fit the restaurant's status (e.g. switching off one that is already off)                                                                                              |
| `PROVISIONING_FAILED`        | 502     | (cloud) creating the restaurant's database or setting it up stopped; the restaurant is saved as FAILED and can be retried                                                                         |
| `LIVE_DISABLED`              | 501     | The server runs without a live stream; screens poll instead                                                                                                                                       |
| `INTERNAL_ERROR`             | 500     | Unexpected error (details only in server logs, correlate with `requestId`)                                                                                                                        |
| `EMPLOYEE_CODE_TAKEN` | 409 | That staff number (or the linked sign-in) already belongs to someone |
| `NOT_EMPLOYED_ON_DATE` | 409 | The person was not employed on that day (before joining, after leaving) |
| `ALREADY_CLOCKED_OUT` | 409 | They already clocked out today; a manager must correct the day |
| `PIN_WRONG` | 400 | Wrong clock-in PIN (never 401: the web app treats 401 as an expired session); `triesLeft` says how many remain |
| `PIN_LOCKED` | 429 | Five wrong PINs: that person is locked out of the clock screen for 5 minutes |
| `HOLIDAY_EXISTS` | 409 | That date is already a holiday |
| `LEAVE_OVERLAP` | 409 | The person already has leave on some of those days |
| `LEAVE_BALANCE_EXCEEDED` | 409 | Not enough leave of that kind is left (`remainingHalfDays`, `requestedHalfDays`) |
| `LEAVE_OVERLAPS_ATTENDANCE` | 409 | Approval refused: they are marked present on a day of the leave (`date`) |
| `LEAVE_ATTENDANCE_LOCKED` | 409 | That day belongs to an approved leave; cancel the leave first |
| `PAYROLL_PERIOD_LOCKED` | 409 | The day is inside an approved pay run (attendance, leave and holidays there are frozen); correct it in the next pay run |
| `PAYROLL_RUN_EXISTS` | 409 | There is already a live pay run for that period and frequency |
| `PAYROLL_NOT_READY` | 409 | A pay run cannot be approved yet (`problems`: UNMARKED_DAYS, NEGATIVE_NET, PERIOD_NOT_FINISHED, NO_PAYSLIPS) |
| `PAYROLL_NOT_EDITABLE` | 409 | The pay run is not a draft any more (or is not yet approved, for payments) |
| `PAYROLL_OVERPAYMENT` | 409 | The payment is more than is still owed on the payslip (`remainingPaisa`), or nothing is owed |

Domain rule violations (bad deal pick, modifier min/max, missing weight, …) return `VALIDATION_FAILED` (400) with a `reason` such as `DEAL_SLOT_COUNT`, `MODIFIER_GROUP_MIN`, `LINE_WEIGHT_REQUIRED`, `TENDER_SUM_MISMATCH` or `DRAWER_INSUFFICIENT_CASH` (paid-out/drop or cash refund larger than the cash in the drawer) or `REFUND_QTY_EXCEEDS` / `REFUND_UNKNOWN_LINE` (credit notes).

Planned (added with their milestones): `TAX_RULE_MISSING`, `TAX_RULE_AMBIGUOUS`, `DISCOUNT_LIMIT`, `IDEMPOTENCY_CONFLICT`.

`STATION_MISSING` is no longer returned: a dish without a station is sent under the default `KITCHEN` station (created on first use) and prints there; the Send response carries a `ticket` (the whole Send as one ticket) whenever a station had no printer, so the screen can print it from the browser (ADR 0036).
